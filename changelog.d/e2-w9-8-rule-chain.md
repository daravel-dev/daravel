### Added

- `daravel_lints` (W9.8): the opt-in rule `string_validation_rule` (`StringValidationRule`) reports a string rule list (`'required|email|max:255'`) where a `Rules` chain means the same, and its message names that chain (`Rules.required().email().max(255)`). The editor completes the chain and the compiler checks it. The rule reports nothing where no exact chain exists (`regex`, an unknown rule, a non-numeric `min`), so the editor fix that follows can always keep the meaning.
- `ruleChainSource(dsl)` writes the chain and mirrors `RuleParser` rule by rule. `dartisan_cli`'s `rule_chain_equivalence_test.dart` (generated by `tool/rule_chain_cases.dart`) checks 128 string lists, one or more per rule name, against the chain written for each: the same rules, parameters and schema hints, and the same validation results on sample inputs.
- `InvalidValidationRule.forEachRuleString` finds the rule strings of a file for both rules.

### Upgrade notes

- New public names `StringValidationRule` and `ruleChainSource` in `package:daravel_lints`. If an application declares either name, importing `package:daravel_lints` makes the reference ambiguous; `hide` the package's name or rename yours. The rule is opt-in, so an existing project is unaffected until it enables it.
