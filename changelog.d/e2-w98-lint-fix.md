### Added

- `dartisan lint --fix` applies the fixes the rules offer (the editor quick fixes: `string_validation_rule`, `string_column_name`) to the files `dartisan lint` reads, leaving findings silenced with `// daravel-lint-ignore:` alone, then runs `dart format` on the files it changed and `dart analyze` on them together with the rest of their library (a part shares its library's imports, so an import a fix adds can break a part that was not changed): a file whose library has errors is compared with its text before the fix (kept in memory, analyzed again), and put back when the fix added errors, which it says. When `dart analyze` does not run (it cannot start, or ends without a verdict) or a write fails (a file open elsewhere, no permission), every file written is put back and the command fails, naming the cause. Each file is written whole (a temporary file renamed over it, keeping its permissions on Linux and macOS), so a killed run never leaves one half written; a `*.lint-fix.tmp` such a run left is removed on the next run (listed with `--dry-run`). `--dry-run` prints the changed lines (Myers' diff: a long file with fixes far apart stays cheap) and writes nothing. Without `--force` it refuses files with uncommitted changes, files git ignores, and a project outside a git work tree, so `git checkout` can always undo it. After fixing it reports what is left, as `dartisan lint` does; with `--json` its own lines go to stderr, so stdout is only the JSON of what is left. A `dart format` that cannot run is reported (the files are still analyzed); a part not generated yet (`part 'x.g.dart';`) is left out of the analysis; git paths are read NUL-separated, so a non-ASCII path is listed as it is.
- `daravel_lints`: `fixSource(source, path, rules:)` applies every fix in a file (a fix left out for an overlap is taken in a later pass), and `lintDirectories` names the folders `dartisan lint` reads.
- `dartisan_cli`: `planLintFixes`, `lintFixDiff`, `lineEdits`, `uncommittedFiles`, `analyzeErrors`, `machineFields`, `libraryFiles`, `writeFileAtomically` and `removeStaleLintFixFiles` (the pieces of `lint --fix`); `LintCommand(analyzer:)` replaces the `dart` it analyzes with (tests).

### Fixed

- The `string_validation_rule` fix (`daravelName`) put the import it adds after the last directive, which could be a `part` (an import after a part does not compile); it now goes after the last import or export, before the parts, and in a `part of` file, which cannot import, no fix is offered.
