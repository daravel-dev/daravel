### Changed

- `boolean:strict` is now honoured, as Laravel 12.x `validateBoolean` reads it: when the first parameter is `strict`, compared exactly (`boolean:strict`, `boolean:strict,x`, and the alias `bool:strict`; `bool` is an alias of `boolean` in Laravel too), only the values `true` and `false` pass and the error is the `boolean` message under the `boolean` key. It was read as plain `boolean`. One difference stays: Laravel does not trim a parameter, so `boolean: strict` and `boolean:strict ` (a space before or after) are not strict there, while Daravel's rule parser trims every parameter of every rule, so they are strict here; `boolean:x,strict` and `boolean:STRICT` are not strict in either. Plain `boolean` is unchanged and still accepts `'true'`, `'false'`, `1.0` and `0.0` (ADR-030). `Rules.boolean({strict})`, `BooleanRule(strict:)` and the `boolean({strict})` step of `RuleBuilder` and rule chains build the same rule.

### Upgrade notes

- A request that passed `boolean:strict` with `1`, `0`, `1.0`, `0.0`, `'1'`, `'0'`, `'true'` or `'false'` now fails with 422; send JSON `true` or `false`, or drop `:strict` to keep the lenient rule. A form (`application/x-www-form-urlencoded`), multipart or query value is always a string, so `boolean:strict` rejects every value sent that way, as in Laravel; use plain `boolean` for form input. A client generated by `client:flutter` checks `boolean:strict` fields the same way once it is regenerated: its pre-check accepts only the Dart values `true` and `false`.
- New public name `BooleanRule.strict` (a field) and a `strict` parameter on `Rules.boolean`, `RuleBuilder.boolean` and `RuleChain.boolean` in `package:daravel` (members of existing classes, so no top-level name is added and no import can clash).
