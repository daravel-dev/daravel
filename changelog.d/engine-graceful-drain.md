### Fixed

- A graceful drain (shutdown, a restart, a rolling deploy) no longer closes connections that were accepted just before it but whose request had not been read yet: `HttpServer.close` counted them as idle and closed them, and the client saw `Connection closed before full header was received` instead of an answer. The engine now listens through `GracefulServerSocket`, which stops accepting new connections first while the server keeps those already accepted, waits `ServeOptions.drainGrace` (250 ms, bounded by the shutdown timeout; zero closes the idle ones at once, as before) for their requests, then closes the idle ones. During the drain every response carries `Connection: close`, so a keep-alive client opens its next connection elsewhere instead of sending on one about to close. `/up` already answers 503 before the drain starts; a connection still in the kernel's accept queue when the drain begins is refused, as before, which is why a load balancer should stop routing on readiness first. `ServerEngine.acceptedConnections` counts the connections accepted.
