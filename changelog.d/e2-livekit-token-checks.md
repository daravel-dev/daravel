### Added

- `JwtCodec(requiredClaims: [...])` and `JwtCodec.hs256(requiredClaims:)`: claims a token must carry to verify (present and not null; `exp`, `nbf` and `iat` a finite number), tymon/jwt-auth's `required_claims`. `JWT_REQUIRED_CLAIMS` (comma-separated) sets them for the JWT guard (`AuthConfig.jwtRequiredClaims`, `exp` when unset), checked at boot by `AuthConfig.check`: a name that is not a claim name stops the boot, a claim the guard does not write into its tokens and an empty list in production are warnings. `LivekitWebhookReceiver.acceptance(maxAge)`: how long an event is accepted, and so remembered by the replay check.

### Fixed

- Security: the JWT guard accepted a signed token without `exp`, which never expires, and any `JwtCodec` skipped an `exp`, `nbf` or `iat` that was not a number, so a token with `"exp": "never"` never expired either. The guard now requires `exp` by default, as tymon/jwt-auth does, and refuses such a token like any invalid one (401, the same answer); a time claim that is there but not a number is always refused, as firebase/php-jwt does. Tokens the guard issues carry `exp`, and `nbf` and `iss` too when they are required. Since 1.0.0.
- Security: `daravel_livekit` accepted a token or webhook token without `exp` (LiveKit's server SDKs require it) and an empty `LIVEKIT_API_KEY`, now refused (`JwtException`, `StateError`); a token's identity with a control character is refused (`ArgumentError`). With `maxAge` (the default), a webhook without an id or a readable `created_at` is refused (401), and the replay check remembers an event id for as long as an event is accepted (`maxAge` plus twice the 30 s skew, six minutes), not 30 s less, so an event dated ahead could be replayed once at the end of its window. A token claim, video grant or webhook field of the wrong type is a `JwtException` or a `LivekitWebhookException` instead of a type error (500), and a `created_at` no number holds reads as missing. Since 1.0.0.

### Upgrade notes

- Upgrading can refuse JWTs: a token without `exp`, or with an `exp`, `nbf` or `iat` that is not a number, no longer signs anyone in (401). Tokens Daravel issued always carry `exp`; tokens from elsewhere without one are refused unless `JWT_REQUIRED_CLAIMS` is set empty (which the boot warns about in production). Requiring claims the guard does not write (anything but `exp`, `iat`, `sub`, `jti`, `nbf`, `iss`, and `aud` with `JWT_AUDIENCE` or `prv` with `JWT_SUBJECT_CLASS`) refuses the guard's own tokens unless the application passes them to `issue(claims:)`. LiveKit: an empty `LIVEKIT_API_KEY` now throws when a token is signed or verified or a webhook received; a webhook without an id or `created_at` is refused while `maxAge` is set (pass `maxAge: null` to check the token only). New public names: `JwtCodec.requiredClaims`, `AuthConfig.jwtRequiredClaims`, `AuthConfig.jwtIssuedClaims`, `AuthConfig.check`, `LivekitToken.requireKey`, `LivekitWebhookReceiver.acceptance`.
