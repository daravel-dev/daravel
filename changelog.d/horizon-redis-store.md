### Added

- `daravel_redis`: the `redis` Horizon store (`HORIZON_STORE=redis` with `withRedis()`; Blueprint #134, H6a). `RedisHorizonStore` keeps what Horizon shows in keys under `REDIS_PREFIX` and the hash tag `{daravel:horizon}` (one slot on a Redis Cluster, so each Lua script runs on one node), written in batches (every 250 ms or 100 jobs, one script each, all keys through `KEYS`, the time through `ARGV`) outside the job's zone, and closed at shutdown. Job lists are bounded by retention and by `HORIZON_STORE_MAX_PER_STATUS` (10 000, `HorizonConfig.storeMaxPerStatus`): about 15 MB of Redis at any rate; a job's hash is deleted, atomically, once no list or monitored tag refers to it. The counts behind `rates`, `summary` and the metric snapshots live in per-second, per-minute and per-hour buckets and a snapshot accumulator, so the list limit never cuts them. Every key but the monitored-tags set expires by itself. A record that cannot be written is counted in `horizon_store_dropped_total{store="redis",reason}`. Measured: 3 ms of Redis time for a batch of 100 records. Tested on a standalone Redis 7.4 and on a three-node Redis Cluster.
- `daravel_horizon`: `HorizonStoreDrivers` (`extend(name, factory)`), through which a package adds a `HORIZON_STORE` (as `withRedis()` adds `redis`), and `BufferedHorizonStore`, the stores `withHorizon()` closes at shutdown (`DatabaseHorizonStore`, `RedisHorizonStore`).

### Upgrade notes

- `daravel_redis` now depends on `daravel_horizon`. A `daravel_redis` release therefore needs `daravel_horizon` on pub.dev at the same version first; the publish job publishes `daravel_redis` after it.
- New public names: `RedisHorizonStore` in `package:daravel_redis`; `HorizonStoreDrivers` and `BufferedHorizonStore` in `package:daravel_horizon` (an application class of the same name and the barrel import give an ambiguous-import error; `hide` it or rename yours). `HorizonConfig` gains `storeMaxPerStatus` (`HORIZON_STORE_MAX_PER_STATUS`; below 1 is a config error).
