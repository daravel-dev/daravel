### Fixed

- `Application.shutdown()` after a password was hashed could end the process before it returned, silently and with exit code 0: a command or seeder that hashed (`Hash.make`/`check`) and then shut down as its last step lost everything after the shutdown, its own output included, and skipped the rest of the shutdown, the database connections' close included. The compute pool waited for its workers' exit on a port that does not keep the isolate alive, so a process with nothing else to do ended inside that wait. Seen every time on Linux; a server is not affected (its sockets keep the process alive). The pool has had this since 1.23.0 (`Concurrency.run`, then `Application.shutdown()` stopping its workers); password hashing runs in such a pool since 1.27.0, which made it the common case. A worker being stopped now keeps the isolate alive until its exit arrives; an idle pool still never holds the process open.
