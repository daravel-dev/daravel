### Fixed

- `in_array` overflowed the stack, a 500, on input nested thousands of levels deep (two lists 8 000 levels deep under `dart run`, 20 000 in a compiled binary) or holding a list or map that contains itself, wherever the rule ran on input that the JSON depth limit did not stop (a `Validator` on data built in code, or `HTTP_JSON_MAX_DEPTH` raised or off). Its `*` crosses dots, so it reads every leaf below the field it names, and it called itself for every level. It now keeps its own stack: 50 000 levels are read like any other input. What it decides is unchanged wherever it gave an answer, checked against the walk as it was over handwritten cases and 6 000 random inputs. A list or map met again inside itself is not walked again and gives no value (a PHP array cannot contain itself, so Laravel has no answer there).
- `in_array` wrote a dotted key at every level of the input, so a chain of lists held text growing with the square of its depth while it was read (4 000 levels: 11 ms and 18 MB in a compiled binary; now under 1 ms and under 1 MB). A key is now written only where a leaf needs one. Ordinary wide input costs about the same: reading 20 000 small maps takes about 13 percent longer, 20 000 numbers the same.
