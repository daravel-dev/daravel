### Added

- `redactUrl(url)`: a URL with the user-info password and the values of sensitive query parameters (`token`, `api_key`, `password`, `signature`, ...) masked, for messages and logs; it needs no valid URL. `redactUrlInText(text)` applies it independently to URL-shaped tokens in a free-form message. Pairs are read after the first `?` or `#`, split at `?`, `&`, `;` and `#` (a fragment of pairs from an OAuth implicit-flow redirect, the query of a URL nested in a value), with names compared percent-decoded and without control characters; `sig`, `key`, `code`, `auth` and `pass` are masked when they are the whole name; a value holding `://` has its user info masked. `sensitiveKeyNames`, `normalizeKeyName` and `isSensitiveKeyName` are the names and the comparison the logger's redaction uses (`LoggingConfig.defaultRedactedKeys` is `sensitiveKeyNames`). `Http.isIdempotent(method)`, `ConnectionException.method` and `ConnectionException.mayHaveBeenSent`.

### Fixed

- Security: the HTTP client's errors (`ConnectionException`, `ResponseTooLargeException`, `StrayRequestException`, a malformed URL) quoted the request URL whole, user-info password and query tokens included, into messages, logs and the debug error page. They now show it through `redactUrl`; the request and `ResponseTooLargeException.url` keep it for code. Since 1.0.0.
- Security: `redactUrlPassword` left a password in a URL without a valid scheme (`app:secret@host/db`, `postgres//app:secret@host`) and masked only the end of one holding `:` (`app:p1:p2@host`). The user info is now found in the authority (after a valid `scheme://`, after a leading `//`, or from the start of the text, up to the first `/`, `?` or `#`) and masked from its first `:` to its last `@`; a password holding `/`, `?`, `#` or `://` is masked whole, and an `@` in the path or query (`?email=a@b`) no longer swallows the rest of the URL. A malformed `DB_URL`, `REDIS_URL`, `UPSTREAM_URL`, `AWS_ENDPOINT` (`daravel_s3`) or `Env.url` value is reported through `redactUrl`, query passwords included; `daravel_reverb`'s `config:show` masks `REVERB_METRICS_URL` even when `Uri` cannot parse it, and `daravel_s3`'s masks `AWS_ENDPOINT` and `AWS_URL`; `reverb:stats --url` and `cache:stats --url` print the URL masked.
- `Http.retryOnConnectionOr5xx` and `Http.retryOnConnectionOnly` sent a `POST` or `PATCH` again after a connection failure that may have followed delivery. They now retry such failures only for an idempotent method (RFC 9110: `GET`, `HEAD`, `OPTIONS`, `TRACE`, `PUT`, `DELETE`); a connection that failed before sending is still retried. `retryOnConnectionOr5xx` still retries every method when the server answers 429 or 5xx, which is an explicit choice by its caller.
- A failed broadcast to Reverb or Pusher quoted the whole response body; it is cut to 120 characters, as Laravel's `RequestException` cuts it.
- A timeout under a second read `0s` in the error message; it now reads in milliseconds.
- Security: `daravel_s3`'s connection errors (refused, timed out, cut off, a body gone quiet) quoted the request URL whole, endpoint password and `X-Amz-Security-Token`/`token` query values included, into messages, logs and the debug error page; they now show it through `redactUrl`, and a timeout under a second reads in milliseconds. Since 1.0.0.
- `daravel_redis`: a password holding `:` in `REDIS_URL` (also Sentinel and Cluster URLs) was read as no password; it is kept whole.
- Logging: a value whose `toString()` threw (in the context, from `toLogValue()`, or the record's error) made the JSON and daily-file handlers drop the record; it is written as `[UNLOGGABLE: <type>]`. The console escapes the channel name too, and every URL-shaped token in the error of a failed readiness check is redacted independently.

### Upgrade notes

- Upgrading can change logs and messages: a log context key containing `signature` (`auth_signature`, `X-Amz-Signature`, `signature`) is now redacted, since `signature` joined the default `LOG_REDACT` keys, and so are query and fragment values with such names; URL-bearing errors show masked URLs, where the values of `sig`, `key`, `code`, `auth` and `pass` are masked too; a `POST` or `PATCH` is no longer retried by the two helpers after any connection failure that may have followed delivery. New public names: `redactUrl`, `redactUrlInText`, `sensitiveKeyNames`, `normalizeKeyName`, `isSensitiveKeyName`, `Http.isIdempotent`, `ConnectionException.method`, `ConnectionException.mayHaveBeenSent`.
