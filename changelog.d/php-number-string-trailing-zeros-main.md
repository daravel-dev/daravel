### Fixed

- Where validation writes a float as text the way PHP's `(string)` does, one kind of float was written without zeros that PHP keeps: an integer of 15 digits whose last digit is 5 and whose 14th digit is even, such as `100000000000005.0`, which PHP writes `1.0000000000000E+14` and Daravel wrote `1.0E+14` (`339499579592405.0`: `3.3949957959240E+14`, was `3.394995795924E+14`). PHP rounds such a tie down to 14 digits on a path of `zend_dtoa` that does not drop the zeros it has written. The text is now PHP's for every double: checked against PHP 8.4.28 over 27 001 doubles (`test/validation/php_float_string_rows_test.dart`, the rows written by `tool/validation/php_float_string_rows.php`), of which the code before wrote 2 392 differently, all of this kind. Comparisons of numbers are not affected (`distinct`, `required_if` and the like compare such a float as a number); only where the text itself is read: `distinct:ignore_case` beside a string, `starts_with`, `ends_with`, `doesnt_start_with`, `doesnt_end_with`, the `:value` of a message, the key a `unique` ignore skips, and the values `exists` on a list counts once.

### Upgrade notes

- For a float that is an integer of 15 digits ending in 5 with an even 14th digit (JSON `100000000000005.0`; the JSON integer `100000000000005` is an int and was always written in full), the outcomes that read its text change to PHP's: under `distinct:ignore_case` the string `"1.0000000000000E+14"` beside it is now a duplicate and the string `"1.0E+14"` no longer is; `starts_with:1.00` now passes for it and `doesnt_end_with:00E+14` now fails; a message shows `1.0000000000000E+14` for it; `unique` with it as the ignored id skips the key `1.0000000000000E+14`; and `exists` on a list counts it apart from `100000000000000.0`.
