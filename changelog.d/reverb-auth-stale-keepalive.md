### Fixed

- `daravel_reverb_client`: a channel authorization `POST` of `EchoAuth.bearer` or `EchoAuth.endpoint` that fails before any answer began (a `ClientException`, as on a keep-alive socket a draining server closed during a rolling restart) is sent once more, so private and presence channels no longer stay unsubscribed after the reconnect. The second request goes out on an HTTP client made for it alone and only when the package made the client itself (a `client` the application gives is asked once), never after an answer started arriving, and both requests share the one `timeout`. The package's own client is now also closed when the WebSocket connection is lost, not only by `Echo.disconnect()`; authorizations still running for a connection that is gone send nothing more, and `Echo.disconnect()` leaves no channel marked subscribed or subscribing.
