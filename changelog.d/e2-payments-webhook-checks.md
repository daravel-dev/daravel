### Fixed

- Security: `daravel_payments` compared a notification's amount with the order's but not its currency: a validly signed notification for 100 IDR paid an order of 100 USD. A notification whose currency differs from the order's (case aside) now changes nothing, answers `amountMismatch` and dispatches `PaymentAmountMismatch`; one without a currency is compared by amount only, as before. Since 1.0.0.
- Security: `MidtransGateway`, `StripeGateway` and `XenditGateway` accepted an empty or blank server key, webhook secret or callback token, with which anyone can sign or pass a notification. Such a key is now an `ArgumentError` when the gateway is made, and a blank `MIDTRANS_SERVER_KEY`, `STRIPE_WEBHOOK_SECRET`, `XENDIT_WEBHOOK_TOKEN` (or any other payment key) counts as unset, so the gateway reports its missing keys (`ConfigException`). stripe-php refuses an empty webhook secret too. Since 1.0.0.
- `daravel_payments` recorded a notification as handled even when it changed nothing, so the gateway's retry was answered `duplicate` and dropped: a notification that arrived before its order was stored never applied, and a Midtrans card `capture` held for review (`challenge`) hid the same `capture` once accepted, leaving the payment `pending`. Only a notification that moved the payment now counts as handled; one answered `unknownOrder`, `unchanged`, `ignored` or `amountMismatch` is looked at again when it comes back. A Midtrans event id now includes `fraud_status` (`<transaction>:capture:accept`). A deadlock or serialization failure while applying runs the transaction again (up to three times). Since 1.0.0.

### Upgrade notes

- Upgrading can change webhook answers: a notification redelivered after it was answered `unknownOrder`, `unchanged`, `ignored` or `amountMismatch` is applied (or answered the same way again) instead of `duplicate`, including one stored by an earlier version as unprocessed; a Midtrans notification with a `fraud_status`, redelivered after the upgrade, gets a new event id and is looked at once more (it finds the payment in its status: `unchanged`). Constructing a gateway with an empty or blank key throws `ArgumentError`. No schema change.
